# Aetheria Modular HTML Motion Engine Guidelines (`film_scaffold` + `script/scene1..N.js`)
We use a deterministic **Modular HTML Motion Engine** (supporting HTML5 2D Canvas, SVG, and 3D WebGL / Three.js depending on the active `/skill`) instead of React/Remotion `.tsx` components AND instead of cramming 1,000+ lines into a single monolithic HTML file.

0. **Harness-First Workflow (`film_scaffold` — Focus Only on Motion & Design)**:
   - Unless extracting an already-moved standalone HTML/SVG stage or building a custom multi-layer HTML/DOM stage (`manageIndexHtml: false`), call `film_scaffold({ title, preset/width/height, background, useThree, scenes: [{ id, duration, audio?, words?, accent? }] })` FIRST.
   - `film_scaffold` automatically creates `projects/<slug>/film.json`, deterministic boilerplate `index.html` (`window.__filmMeta`, `SCENES`, `window.renderAt(t)`), and idempotent `script/scene1..N.js` stubs, and `write`/`edit` auto-resolve `script/...`, `audio/...`, and `index.html` directly into the active project folder.
   - Then spend 100% of your effort crafting rich procedural visuals, shading, typography, and motion beats inside each `script/sceneK.js`'s `AM.registerScene("<id>", function (ctx, localTime, dur, scene, AM) { ... })` body.

1. **Why Per-Scene Modular Scripts (`script/scene1.js` .. `sceneN.js`) Are Mandatory**:
   - NEVER cram all scenes of a multi-scene video into a single giant `index.html` file. Writing 1,000+ lines in one file hits LLM output token limits and degrades animation quality on later scenes.
   - Instead, write **one modular script per scene** in `script/scene1.js`, `script/scene2.js`, ..., `script/sceneN.js` (~120–180 lines each), and use full-file `write` (not multi-line `edit` diffs) when creating or updating short scene scripts (reserve `edit` with `startLine`/`endLine` for tiny <=25-line tweaks).
   - Each `script/sceneK.js` registers its renderer via `AM.registerScene`:
     ```js
     (function () {
       var AM = window.AM;
       AM.registerScene("scene1_hook", function (ctx, localTime, dur, scene, AM) {
         // 3-4 sequential visual beats using localTime, dur, scene.accent, AM.spring, AM.ease, etc.
       });
     })();
     ```
   - `AM.getSceneRenderer(scene.id, resolved.index)` automatically resolves by exact `scene.id` (e.g. `"scene1_hook"`), 1-based `"scene1"`, or 0-based `index` (`0`), and runs inside `try / catch` so a typo in one scene never crashes the entire video player.
